# 自然语言双 Agent 自动协作 V1

## 已确认目标

以简化后的业务模拟人为基础，自动驱动业务参与者与被测角色协作到约定阶段结束。
知识、角色职责与流程控制分离；不恢复旧 Oracle 的答案选择和完成动作协议，不要求操作员主持每轮。
运行器与控制器使用同一个入口：运行层负责调用、隔离与证据，控制层负责路由、有限推进及结束核验。

## 启动约定

所有约定通过配置传入，默认如下：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| allowPendingDraft | true | 启动时授予基于已讨论证据生成待决草稿的权限；不批准业务待决 |
| callLimit | 10 | 双方合计最多十次模型调用，失败调用也占用预算；不是十轮，不包含 CLI 版本查询 |
| disableBuiltinMcps | true | 被测角色默认使用本地文件工具；参与者始终无工具、无 MCP |
| skipIssueRegistration | true | 测试交付不以 Issue 登记为前提；远程事项保留跟进 |
| requireArtifact | true | 默认阶段目标要求真实文件交付；可配置为仅讨论 |
| maxCoordinatorPrompts | 1 | 全会话最多一次中性协调追问，可配置文案 |
| maxIdenticalReplies | 3 | 同一角色连续完全相同回复达到此数量时停止 |
| minimumParticipantReplies | 0 | 独立入口不强制提问；双条件比较默认 1，防止没有交互便结束 |
| timeoutSeconds | 900 | 每次模型调用超时，可配置 |

任务初始需求、角色与模型、私有知识、工具权限、产物描述、输出位置均可配置。
模拟人明确选择模型，不自动回退。被测角色可显式选择 auto 作为比较条件，记录逐次实际模型证据；
固定模型必须与实际模型匹配。知识与执行协议冻结于本次运行，改变输入需新建运行。
首版直接在配置的产品仓库工作，可写文件；应使用专门测试工作区，私有证据不得放入产品或框架仓库。

## 角色约定

被测角色负责发现具体问题、调查获准范围内的基线、整理并交付自身任务。
业务参与者只回答实际问题，保留未知与冲突；不主动补漏，不评分，不批准完整性、实施或发布。
模拟人的收到、范围限定和没有补充不构成批准。
双方完成自身任务后正文明确表达“角色任务已经完成”，同时报告机器可读状态。
首版通过启动消息与每轮约定适度覆盖角色的输出格式限制，不修改产品角色源文件。

## 消息约定

正文仍是自然语言。最后一行固定为 `DIALOGUE_CONTROL: ` 加单行 JSON，字段仅为
`status`、`artifactPaths` 和 `pending`。元数据不是业务规则，不送入另一方的业务正文。

| status | 中文含义 | 调度 |
| --- | --- | --- |
| waiting_reply | 交给对方继续处理 | 提问和业务答复都转发正文；不要求正文一定包含反问 |
| role_task_completed | 角色任务已经完成 | 被测角色提交完成核验；参与者最后有效回答仍先送达被测角色 |
| blocked | 无法继续 | 被测角色说明外部阻塞后结束；参与者不能直接终止被测任务 |

仅支持以上三个状态，已取消 no_reply；旧状态不再被当前解析器接受。
回答完一个问题不等于整个角色任务完成，参与者通常用 waiting_reply 交回本轮答复。
参与者非空正文不因角色完成或阻塞状态而丢弃；
预算耗尽或执行失败仍可阻止下一次调用，此时不得标成已送达。
转发后以对方成功调用的实际输入捕获与构造输入一致作为交付凭据，纯路由意图不算送达。
报告分别记录等待送达、已捕获送达和未转发；接收消息不等于对方已经收到。

`artifactPaths` 为实际交付的仓库相对路径。每个 `pending` 项含稳定编号 `id`、原问题
`question` 和 `kind`。类型为业务待决、基线核实、技术跟进或尚未分类，分别使用
`business_decision`、`baseline_investigation`、`technical_followup`、`unclassified`。
同编号可修改当前 question 并附 answeredParts、remainingQuestion、questionStatus，程序保留 originalQuestion 和修订 history。
questionStatus 区分 awaiting_reply、answered、partially_answered、pending。result.json 的 questions 保存全部问题，
pending 仅派生真正未决及部分回答项。首次提问不是已确认的未知业务选择，完成声明也不能替代答复。
参与者明确 answered 时必须提供非空回答片段且无剩余问题，允许依据该答复关闭对应待决；PM 不能自行关闭。
兼容只列未决的业务答复：最新提问批次中此前 awaiting_reply 且未列出的项目可标为已回答推断，
引用该次参与者答复作证据，但语义仍须评审。已经登记的真正待决不能通过省略或降级为 awaiting_reply 消失。
分类仍须保持一致；保留历史状态变化，不实现人工追加批准接口。

## 未知与结束

未知不等于保持现状、不支持或默认批准；继续处理其他独立问题。基线由被测角色调查，技术问题留作跟进。
没有新依据不反复索取同一决定；知识冲突保留，不自动选边。

Agent 先声明自身状态，控制器再核验。声明不代替文件，文件不证明内容质量。
文件必须非空、位于仓库内、无链接路径，且本次新建或发生内容变化。
草稿引用仍未决编号，区分确认内容与剩余未决，允许概括及等价措辞；原问题和回答证据由会话台账保存。
确定性控制器只核验真实文件及未决编号引用，不要求自然语言逐字匹配，不宣称已验证语义完整或批准质量。
已回答问题不再是待决交付阻塞项；尚未回答的实际问题即使在不要求文件的讨论阶段也不能被跳过。
artifactCheck 保存 ready、verifiedPaths、failures 与 semanticValidation；失败项注明路径、问题编号和原因，
例如 artifact_not_found、artifact_unchanged、pending_reference_missing、question_not_answered。
不允许带待决起草时，带待决的完成声明按外部阻塞结束，不擅自授予许可。

最终结果区分 `stage_completed`、`completed_with_pending`、`blocked_external`、
`stalled`、`budget_exceeded`、`failed`。最后一次预算内调用仍可成功交付，绝不额外启动一次。
无交付或无有效下一步时，可追问“还有问题吗？”，不能利用隐藏知识提示遗漏。
完成声明未通过文件核验时，优先明确要求核对产物及待决证据，避免用笼统追问掩盖交付问题。
协调次数仍受 maxCoordinatorPrompts 限制；耗尽后明确停滞，不无限追问或互发收到。
默认同一角色连续三次完全相同回复停止，阈值可配置；这只是精确重复保护，不宣称能识别语义改写。
协调预算、模型调用预算耗尽或错误都不得伪装成功。隐藏知识覆盖率只用于事后独立评估。

## 实现与验收

复用现有采集器的 CLI 传输、固定 session ID、隔离参数、实际模型证据及前后 Git 快照。
不修改旧矩阵、Oracle、JSON 知识参与者或历史证据。
首版支持 Markdown 知识与自然语言参与者；JSON knowledge-participant 协议暂不适配。
失败不自动重发，证据保留；首版暂不恢复中断运行。

验收覆盖自动问答与交付、待决保留、预算边界、口头假完成、旧文件假交付、收到不回声、
参与者完成不冒充全局完成、配置覆盖、协议拒绝及私有知识不进入被测提示。
假 CLI 证明程序行为，不能证明真实模型的相关性、完整性、未知分类或状态判断；真实试跑单独开展。
